## What was learned

- **The dogfood worked.** The tool's pitch is "the diagram is the product;
  the source is reference material." The session proved a stronger pitch:
  a baked state diagram is a low-entropy shared surface for agent–human
  system design talk. The diagram and the argument about the diagram
  inhabit the same surface (Glow), with no renderer switch.

- **State diagrams surface constraints as missing edges.** Flowcharts hide
  constraints by only showing permitted paths. State diagrams make you earn
  every permitted path and leave the forbidden ones as conspicuous
  absences. That's why they're the right type for workflow design.

- **Diagram-based reasoning is Gestalt, not Shannon.** The visual structure
  is perceived as a whole before any individual node is read. A dangling
  node is *seen* before it is *named*. The Shannon connection is indirect:
  the diagram is a low-entropy representation of a high-entropy process.

- **The split-the-diagram lesson.** When the renderer can't lay out a
  diagram, that's a signal to split, not to persevere. Same principle as
  the newup discipline: when the unit of work is too big, split it.
